### 1. Подготовка данных (Критически важно!)

Код ищет папку `letters/` в **корне** проекта (на одном уровне с `pom.xml` и папкой `src`). Без неё программа упадет с ошибкой `java.io.IOException`.

1.  Создай папку `letters` в корне проекта.
2.  Помести туда несколько изображений букв (например, `A.png`, `B.png`, `C.png`).
    *   **Формат:** PNG.
    *   **Цвет:** Желательно черно-белые (или четкие цветные, так как код конвертирует их по порогу яркости).
    *   **Размер:** Небольшие, например, **20x20** или **40x40** пикселей. (Код автоматически удваивает разрешение при загрузке, так что 20x20 станет 40x40).

> **Совет:** Для теста можно просто нарисовать в Paint черную букву на белом фоне и сохранить как PNG.

### 2. Сборка проекта через Maven

Открой терминал в корне проекта (где лежит `pom.xml`) и выполни:

```bash
mvn clean compile
```

Это создаст папку `target/classes` со скомпилированными `.class` файлами.

### 3. Запуск и проверка режимов

Так как это консольное приложение, запускать его нужно с аргументами.

#### Сценарий А: Проверка восстановления одной буквы
Этот режим покажет, может ли сеть запомнить букву, добавить к ней шум и восстановить обратно.

**Команда:**
```bash
java -cp target/classes by.bsuir.lab2.Main single -l A -n 0.2
```
*   `-l A`: тестируем букву, соответствующую файлу `A.png`.
*   `-n 0.2`: добавляем 20% шума.

**Что должно произойти:**
1.  В консоли появится сообщение: `Результат сохранен в out.png`.
2.  В корне проекта появится файл **`out.png`**.
3.  **Открой этот файл.** Он должен состоять из трех склеенных картинок:
    *   Слева: Оригинал.
    *   В центре: Зашумленная версия.
    *   Справа: Восстановленная версия (должна совпадать с оригиналом или быть очень похожей).

#### Сценарий Б: Тестирование всех образов
Этот режим проверяет, не путает ли сеть образы друг с другом.

**Команда:**
```bash
java -cp target/classes by.bsuir.lab2.Main test-all -n 0.2
```

**Что должно произойти:**
1.  В консоли пробегут логи обучения и восстановления.
2.  В конце будет итог, например: `Успешно восстановлено 3/3 образов (100.00%)`.
3.  Создастся папка `recalled/`. В ней для каждого образа будут лежать файлы `_original`, `_noisy`, `_recalled`. Можно визуально оценить качество.

#### Сценарий В: Построение графиков
Самая долгая часть, нужная для лабораторной работы.

**Команда:**
```bash
java -cp target/classes by.bsuir.lab2.Main graphs
```

**Что должно произойти:**
1.  Программа начнет по очереди просчитывать данные для трех графиков (это может занять время, от 10 секунд до минуты).
2.  В консоли будут выводиться таблицы данных.
3.  В корне проекта появятся файлы:
    *   `avg_relaxation_vs_noise.png` (График 1)
    *   `avg_relaxation_vs_size.png` (График 2)
    *   `training_vs_patterns.png` (График 3)
    *   Текстовые файлы `table_1.txt`, `table_2.txt` и т.д.

### 4. Возможные проблемы и решения

1.  **`IOException: Can't read input file` / `Не найдено изображений`**:
    *   Проверь, что папка называется именно `letters` (в нижнем регистре).
    *   Проверь, что она лежит в корне проекта (рядом с `pom.xml`), а не внутри `src`.

2.  **`OutOfMemoryError`**:
    *   Если картинки слишком большие (например, 1000x1000), матрица весов (1000*1000)^2 займет гигабайты памяти. Используй картинки до 100x100 пикселей.

3.  **Низкий процент восстановления**:
    *   Сеть Хопфилда плохо работает, если образы сильно коррелируют (очень похожи, например `E` и `F`). Попробуй сделать буквы более разнообразными.
    *   Попробуй уменьшить шум (`-n 0.1`) или увеличить количество итераций.
